SUMMARY

What v1.2.0 implemented:
- `android-compose` as a third greenfield starter profile, alongside
  `typescript-cli` and `nextjs-app`, selectable only explicitly (directly or
  via a small bounded alias table), never as a silent default.
- Required `setupCommands`/`validationCommands` fields on the shared
  `GreenfieldProfile` contract, flowing through bootstrap-bundle and
  scaffold-plan generation in place of a hardcoded npm assumption.
- Profile-conditional validation: Android/Jetpack/Kotlin/Gradle content is
  legitimate only for `android-compose`; unsupported-platform (iOS/React
  Native/Flutter/multiplatform) and Play Store/release-readiness claims
  remain rejected for every profile.
- Full CLI/check/export regression coverage, plus 6 corrected static
  stage-prompt lines that had blanket-forbidden Android/mobile content from
  before this profile existed.
- A fully audited and repaired documentation set, plus a hardened
  `docs:check` that extracts the supported profile list from source instead
  of a hardcoded regex, and no longer false-positives on legitimate "supports
  Android Compose" claims.

What was intentionally not implemented:
- No CLI `--profile` flag and no automatic signal-based routing to
  `android-compose` (both were in the original roadmap sketch but were a
  deliberate scope decision, not built -- see docs/ROADMAP.md's "Implemented
  v1.2.0" deviations note).
- No Gradle execution, no Android SDK requirement/detection, no Play Store
  readiness logic, anywhere in the orchestrator.
- No Flutter, React Native, or iOS support; no generic mobile mode.
- No brief-schema changes of any kind across all five batches.
- No publish, tag, or GitHub release; package.json version remains 1.1.0.
