SUMMARY

What was implemented:
- android-compose registered as a third GreenfieldProfileId and fully specified GreenfieldProfile (src/greenfield/profiles/androidComposeProfile.ts), per the Batch 1 contract.
- GreenfieldProfile gained two new required fields, setupCommands and validationCommands (a minimal, non-executed command-description shape), backfilled onto the existing typescript-cli and nextjs-app profiles to preserve their current behavior exactly.
- Profile resolution gained a small, explicit, bounded alias table (android, kotlin-compose, jetpack-compose, compose-android) and the first real use of the 'unresolved' status for generic mobile ambiguity ("mobile", "mobile app", "phone app"), applied both to explicit preferredProfile requests and to fallback free-text signals.
- iOS, Flutter, and React Native remain unaliased and unsupported, regression-tested.
- 2 pre-existing tests whose "android-compose is unsupported" assumption predated this batch were fixed (not weakened) to reflect the new, intentional behavior.

What was intentionally not implemented:
- Bootstrap bundle, project docs bootstrap, and scaffold planning integration (Batch 3).
- CLI/check/export regression coverage (Batch 4).
- User-facing documentation updates (Batch 5).
- Technology-specific fallback auto-selection (e.g. bare `platformTarget: 'android'` -> android-compose without an explicit preferredProfile) -- deliberately deferred as an open design question, not silently added.
